# 客户分层规则与阈值说明

> 分层结果由 `src/segmentation.py` 计算，阈值写入 `segment_threshold` 表供 SQL 视图读取，
> Python 与 SQL 两侧使用同一数据源，避免各自硬编码导致漂移。

## 六层的定义与优先级

分层为互斥的六类，按优先级从高到低判定，命中即停。第一层「零 MRR」：末月 MRR 等于 0。注意这些账户仍持有有效订阅，只是订阅金额为 0，属于计费数据异常而非流失，不能与流失混为一谈。第二层「风险关注」：升级工单数不低于 2，或平均 CSAT 不高于 3.0，或错误率不低于 90 分位。第三层「高价值」：MRR 不低于 75 分位。第四层「深度采用」：使用功能数不低于 75 分位。第五层「浅层采用」：使用功能数不高于 25 分位。第六层「稳健基础」：未命中以上任何条件。

## 阈值取值与来源

全部阈值来自实际分布而非经验值：MRR 的 75 分位为 3,184 美元；使用功能数的 25 分位为 24、75 分位为 32；错误率 90 分位为 0.394；CSAT 低分界取 3.0，因为实测取值只有 3 到 5；升级工单异常线取 2，因为实测最大值为 3。风险层刻意取 90 分位而非 75 分位：若用 75 分位，按定义必然圈进四分之一的账户，风险层会变成什么都装的垃圾桶，首版实测占比 46.8%。

## 分层结果与收入集中度

六层规模为：零 MRR 69 户、风险关注 93 户、高价值 102 户、深度采用 63 户、浅层采用 58 户、稳健基础 115 户。高价值层以 20.4% 的账户数贡献了 57.1% 的收入；风险关注层持有 22.9% 的收入；两层合计不到四成账户撑起八成收入。浅层采用层户均工单 4.74 次，为六层最高，但 CSAT 并不最低，说明这一层的问题是「不会用」而不是「不满意」。

## 阈值敏感性必须披露

使用功能数的分布极窄，25 分位与 75 分位只差 8 个取值点。把关键阈值上下浮动 20%，深度采用层会在 5 户到 167 户之间剧烈跳变。因此采用类分层只能用于描述性分群，不能对外宣称「深度用户占 12.6%」这类结论。MRR 分布连续、分位稳定，所以高价值、风险关注、零 MRR 三层可以放心用于资源分配。敏感性可通过 `python scripts/segment_accounts.py --sensitivity` 复现。

## 使用分层前必须知道的两件事

第一，深度采用层的流失事件率为 81.0%，是六层中最高，且户均 MRR 只有 1,125 美元。「用得深」在这份数据里不是留存的保护因素，但该层仅 63 户且阈值敏感，此结论只能作为待验证假设。第二，风险关注层的判断条件之间是「或」的关系，命中不同条件的账户业务含义不同：因错误率入层的要修产品，因 CSAT 入层的要修服务，不可用同一套动作处理。

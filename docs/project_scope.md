# 项目范围说明（Project Scope）

> 编制日期：2026-11-02　｜　对应任务书：§1 项目范围
> 本文件只回答一个问题：**做什么、不做什么、边界在哪**。
> 详细设计与勘误见 [`00_requirements_and_design.md`](00_requirements_and_design.md)。

---

## 1. 一句话定义

以模拟 B2B AI SaaS 产品为背景，用可复现的公开合成数据，完成「指标体系 → 用户分层 → 运营策略 →
A/B 实验 → AI 使用分析 → RAG 运营诊断」的完整链路，并以「指标由代码计算、LLM 只生成文字」为架构红线。

---

## 2. 六个模块与边界

| 模块 | 做什么 | 明确不做 |
|---|---|---|
| A 指标体系 | 账户级活跃、激活、留存、功能渗透、收入、AI 请求质量 | 不做用户级（user）指标——数据无此粒度 |
| B 行为与分层 | 激活漏斗、Cohort 留存、功能采用、六层客户分层 | 不把自定阈值包装成「行业标准」 |
| C 运营策略 | 新客激活 / 功能采用 / 低活跃维护 三套策略 | 不声称已执行真实触达或改配置 |
| D A/B 实验 | 新手引导对 7 日首次有效任务完成率的影响 | 不把模拟结果写成线上业务成果 |
| E AI 使用分析 | 请求量、成功率、P95 延迟、Token、估算成本 | 不推断回答质量；不称「真实服务成本」 |
| F RAG 助手 | 12 份知识文档 + 本地向量库 + 三场景诊断 | 不做复杂 Agent、不让 LLM 生成任意 SQL |

---

## 3. 硬约束（违反即返工）

1. 所有指标先由 SQL / Python 计算，LLM 不得编造或二次计算数字。
2. RAG 只检索知识库；结构化数据只走三个白名单函数，参数需校验。
3. 不使用 Streamlit、Power BI、Docker、FastAPI、复杂 Agent / 多智能体框架。
4. 不训练大语言模型；Embedding 本地推理，LLM 走 API。
5. 未经确认不做需要管理员权限的安装、删除、覆盖、重置操作。
6. 每个阶段先测试通过，再 Git 提交。
7. 不得声称未实际执行并检查过的测试或推送成功。

---

## 4. 数据边界

| 层级 | 内容 | 表述约束 |
|---|---|---|
| T1 | RavenStack 五表（公开**合成**数据） | 只能说「公开合成数据集」 |
| T2 | `ai_request_logs.csv`（模拟日志） | 必须标「模拟」 |
| T3 | `ab_test_simulated.csv`（模拟实验） | 必须标「模拟实验，仅演示分析方法」 |

原始 CSV 因上游仓库未声明 LICENSE，**不随本仓库分发**，由脚本重建并记录 sha256。

---

## 5. 统计主体约定

全项目主体为 **account**（企业账户）。数据中不存在 user 级表，因此：

- DAA / WAA / MAA（日/周/月活跃账户数）——可计算；
- 「人均使用功能数」实际为「户均使用功能数」——命名必须如实；
- 指标字典中每项标注 `可计算 / 部分可计算 / 不可计算` 及原因，**不允许用近似值填充**。

## 0. 结论摘要

但存在 **5 个会直接改变分析口径的实质问题**，其中 1 个足以推翻任务书模块 B 的原始设计：

| # | 问题 | 严重度 | 后果 |
|---|---|---|---|
| 1 | **时间轴不连贯**：490/500 账户首次使用早于注册日 | 致命 | 「注册→首次使用」激活漏斗在该数据集上不成立 |
| 2 | `feature_name` 为 `feature_1..40` 编号 | 高 | 不能称为「AI 问答/总结/写作」 |
| 3 | 流失三处口径不一致（600 事件 / 352 账户 / 110 标记） | 高 | 流失率算出来会有三个不同数值 |
| 4 | 订阅一对多且同月重叠（4,695/5,257 组） | 高 | MRR 直接求和会重复计入 |
| 5 | `usage_id` 重复 21 行（整行不重复） | 中 | 去重方式选错会误删业务事件 |

**没有发现的问题**（同样值得记录，说明数据在结构上是可信的）：
主键无冲突、外键零孤子、无倒挂日期区间、无整行完全重复。

## 2. 五个关键问题的深度分析

### Q-23 / Q-15 / Q-24：时间轴不连贯（最严重）

**现象：**

- 490 / 500 个账户的**首次使用日早于注册日**，中位数为早 **400 天**，最早早 724 天；
- 76.6% 的使用记录（19,142 / 25,000）早于其所挂订阅的开始日；
- 使用记录落在该账户**任一**订阅区间内的比例仅 **22.5%**。

**判断：** 这不是个别脏数据，而是**生成器未约束时间维度**——`feature_usage.subscription_id`
是随机挂接的，与订阅/账户生命周期没有因果关系。

**后果（直接影响任务书模块 B）：**

任务书要求的新客激活漏斗是
「注册 → 首次 AI 请求 → 首次成功任务 → 7 日内重复使用」。
该链路依赖 `signup_date` 作为 t0。实测结果：

| 指标 | 实测值 |
|---|---|
| 首次使用落在注册后 0–7 天的账户 | **7 / 500** |
| 首次使用早于注册的账户 | 490 / 500 |

7 个账户不足以支撑任何分层或实验。**若照原设计硬算，得到的分母是 500，分子是 7，
激活率 1.4%——这个数字是数据缺陷的产物，不是业务结论。**

**处置：** 见 §3 决策 D-1。

### Q-17：流失有三套口径，互不相等

| 口径 | 数值 | 含义 |
|---|---:|---|
| `churn_events` 事件行数 | 600 | 含同一账户多次流失与复活 |
| `churn_events` 去重账户数 | 352 | 至少流失过一次的账户 |
| `accounts.churn_flag = True` | 110 | 账户快照标签 |

三者交叉：同时在两处的 **75** 个；仅 `churn_flag` 的 **35** 个；仅在事件表的 **277** 个。
另有 **61 条** `is_reactivation=True`，即流失后又复活。

**后果：** 同一句"流失率 22%"（110/500）与"流失率 70%"（352/500）都能从这份数据里算出来，
若不指定口径，报告就不可信。

**处置：** 见 §3 决策 D-2。

### Q-19：同一账户同一月出现多条有效订阅

5,257 个「账户-月」组中，**4,695 组（89.3%）**存在多条同时生效的订阅。
直接 `SUM(mrr_amount)` 或在订阅表上 `COUNT(*)` 都会严重重复计入。

**处置：** 采用确定性胜出规则（任务书对齐上游仓库的建模方式）：

```
同一 (account_id, 月份) 若多条有效订阅，按
  1) start_date 最新
  2) mrr_amount 最高
  3) subscription_id 最大
排序取第一条
```

这条规则会写入 `sql/01_create_tables.sql` 的视图定义与指标字典，保证 SQL 与 Pandas 两侧一致。

### Q-22：`feature_name` 是编号，不是 AI 功能

实测取值为 `feature_1` ~ `feature_40`，共 40 个，分布均匀（每个约 620 条）。
**数据中不存在「AI 问答 / 文档总结 / AI 写作」这类语义。**

**后果：** 任务书模块 B「AI 功能采用分析：问答、文档总结、写作等模拟功能」与模块 E 的
AI 功能维度，**无法在真实数据上完成**。把 `feature_12` 说成「AI 问答」属于编造。

**处置：** 见 §3 决策 D-3。

---

### Q-05：`usage_id` 重复 21 行，但整行不重复

- 25,000 行、24,979 个唯一 `usage_id`，重复超额 21 行；
- **整行完全重复 = 0**。

说明这 21 条不是复制粘贴的脏数据，而是"同一个 ID 对应了不同的事件内容"——更可能是
ID 生成碰撞。因此**不能按 `usage_id` 去重**（会丢掉 21 条真实事件）。

**处置：** 保留全部 25,000 行；若需唯一键，使用
`(usage_id, subscription_id, usage_date, feature_name)` 组合键；
在 `data/processed/` 输出时增加 `dup_usage_id_flag` 列以便追溯。原始行数与去重后行数同时留档。

## 3. 处置决策

| 编号 | 决策 | 理由 | 影响模块 |
|---|---|---|---|
| **D-1** | 真实数据**不再声称**能构建「注册→首次使用」漏斗。改为双轨：<br>① 真实数据以 **`first_use_date`** 为 t0，做「使用起始后的 7/30 日留存」，指标名不带"注册"二字；<br>② 「注册→首次请求→有效性→7 日复购」漏斗改用 **T2 模拟日志**（含 `account_id` 与 `request_time`，可按 `signup_date` 对齐），全程标注模拟。 | 真实数据时间轴不成立；模拟数据本就是任务书允许且要求的扩展数据 | B、D |
| **D-2** | 流失主口径 = **`churn_events` 去重账户**；`is_reactivation=True` 的行单列为"复活"，不重复计入净流失；`accounts.churn_flag` 降级为**交叉校验字段**，不一致的 277/35 个账户在报告中披露。 | 事件表有日期与原因，可做时间序列；快照标签无法追溯。 | A、B、C |
| **D-3** | 「AI 功能」维度只用 **T2 模拟日志**（AI 问答 / 文档总结 / AI 写作）。真实数据的功能分析统一称「**功能渗透（feature_1..40）**」，不映射到 AI 语义。 | 避免把编号功能包装成 AI 能力，属于数据真实性红线 | B、E、F |
| **D-4** | `usage_id` 不去重，加标记列；组合键替代唯一键。 | 整行不重复，去重会丢真实事件 | 全部 |
| **D-5** | MRR 一律走「账户-月胜出规则」视图，禁止对订阅表直接求和或计数。 | 89.3% 的账户-月组存在重叠 | A、C |
| **D-6** | CSAT 分母取 `satisfaction_score` 非空记录（1,175 条），报告必须披露实际 N 与 41.25% 的缺失率。 | 空值不代表 0 分 | A |
| **D-7** | 成本分析只用 T2 模拟日志 + 明示假设单价（快照 2026-09-18）。 | 真实数据无 token/latency 字段 | E |

## 4. 对后续模块的影响（必须提前接受）

| 模块 | 影响 | 应对 |
|---|---|---|
| A 指标 | 「首次有效任务完成率」无 `task_success` 字段，只能用 `error_count = 0` 作**代理**；指标字典须标注"代理口径" | 指标字典增加"口径类型"列：真实 / 代理 / 模拟 |
| B 分层与漏斗 | 激活漏斗改走模拟数据；真实数据只做功能渗透、订阅结构、工单、流失四类 | 已在 D-1 / D-3 固化 |
| C 策略 | 策略 1（新客激活）的证据必须来自模拟数据，报告中需显式声明 | 策略手册标注证据来源层级 |
| D A/B | 见下节 | — |
| E AI 使用 | 真实数据无 token/延迟，全部依赖 T2 | 已在 D-7 固化 |
| F RAG | 知识库文档中的指标定义必须与实际口径一致，不能写"注册后 7 日激活率" | 指标文档按 D-1 措辞 |

### 对 A/B 实验（模块 D）的直接结论

数据只有 **500 个账户**。按 D-1，若以"注册后 7 日内完成首次使用"定义激活，
合格样本仅 **7 个**，实验不可行。

即便放宽到"首次使用后 7 日内留存"作为主指标，可用账户也只有 500 个
（每臂 250）。按设计文档表 2，基线 0.25 时每臂 250 只能检测 **约 47% 的相对提升**
（绝对提升 ≈ 0.118），远高于运营现实中可期望的效果量。

**因此模块 D 的结论是确定的：** 模拟实验必须按**设计样本量**生成（而非复用 500 个账户），
并在报告中写明"样本量为设计值，非真实观测数"。这也验证了设计基线 C-04 的预判。

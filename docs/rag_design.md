## 1. 知识库构成：两类来源，必须分开标注

12 份文档按来源分为两类，front-matter 的 `doc_type` 字段区分。
**这个区分不能省**——它决定了某段内容能不能作为"数据事实"引用。

| 类型 | 份数 | `doc_type` | 内容性质 | 引用时的表述 |
|---|---:|---|---|---|
| 实测派生 | 6 | `derived-from-analysis` | 数字来自本项目真实计算，可追溯 | 可直接称"本项目实测" |
| 模拟产品资料 | 6 | `simulated-product-doc` | 产品与流程设定，**不代表任何真实产品** | 必须称"模拟资料" |

| # | 文档 | 类型 | 承担的问题 |
|---|---|---|---|
| 01 | 指标口径手册 | 实测 | 激活/留存/流失三口径、MRR 取数 |
| 02 | 客户分层规则 | 实测 | 六层阈值、收入集中度、敏感性 |
| 03 | 激活漏斗与数据限制 | 实测 | 为什么注册漏斗不可构造 |
| 04 | AI 使用与成本口径 | 实测 | P95 最近秩法、成本假设、集中度 |
| 05 | A/B 实验协议 | 实测 | SRM、Newcombe CI、三重决策框架 |
| 06 | 数据可计算性边界 | 实测 | 6 项可做 / 7 项不可做 |
| 07 | 产品说明与套餐体系 | 模拟 | 40 功能位、三档套餐、席位模型 |
| 08 | 新手引导标准流程 | 模拟 | 七日路径、三条设计原则 |
| 09 | 工单分级与升级 | 模拟 | 四级优先级、升级触发条件、CSAT |
| 10 | 流失挽回与复活 | 模拟 | 六个原因码、反对无差别折扣 |
| 11 | 定价与扩容 | 模拟 | 扩容三信号、席位背离的含义 |
| 12 | 故障响应与复盘 | 模拟 | 四问结构、2026-06 案例 |

**为什么选择混合而不是全模拟：** RAG 的评估质量取决于"知识库里是否真有答案"。
若 12 份全部编造，再去评估"能不能检索到"，很容易变成自己出题自己答，
指标好看但没有意义。6 份承载项目硬数据的文档保证 ground truth 可靠，
6 份模拟文档负责覆盖真实 RAG 场景（产品、流程、SOP）中的提问方式。

## 2. 切块策略

### 2.1 三个层次的切分顺序

1. **先按 H2 分节。** 一个 H2 节如果整体不超过上限，就整节成块——强行按字数切
   会把一条完整规则拦腰截断，检索到半条规则的害处大于块偏大。
2. **节内超长再切时**，边界优先落在段落，其次句末标点，最后才是硬切。硬切是兜底。
3. **前言合并。** H1 之后、首个 H2 之前的内容通常只有一两句（"本文为模拟资料"之类），
   单独成块会变成 50~90 字的弱检索单元。若它短于下限且后面还有小节，并入第一节。

### 2.2 实测参数

| 参数 | 配置值 | 说明 |
|---|---:|---|
| `CHUNK_TARGET_CHARS` | 350 | 仅用于**切分超长节**时的目标长度 |
| `CHUNK_MAX_CHARS` | 420 | 硬上限，超了就切 |
| `CHUNK_MIN_CHARS` | 150 | 低于此值的前言块会被前向合并 |
| `CHUNK_OVERLAP_CHARS` | 70 | 相邻块重叠字数 |

**实际产出（67 块）：** 最短 102 字、中位 159 字、最长 314 字；token 数最大 272，
全部低于模型 512 上限，无任何一块被截断。

> **一个必须澄清的偏离：** 设计时按 320–380 字设目标，实际块长中位只有 159 字，
> 因为本文档的 H2 节本身就是 150–250 字。这里**没有**为了凑到 320 字而把相邻小节
> 合并——合并会让一个块横跨两个主题，反而降低命中精度。
> 350 字的目标值只对"超长节如何切"生效，不约束"短节是否合并"。
> 换句话说：块偏小是文档结构决定的，不是切块器没按参数执行。

### 2.3 为什么 420 而不是 500

实测字符/token 比约 **1.005**（200 字 → 202 token），500 字块 = 502 token，
恰好卡在 512 边界上，任何一点英文术语或数字就会溢出。
420 字只用到 422 token，留 90 token 余量。

注意：**这个上限不是被模型容量逼出来的**——500 字其实也能放进去。
选 420 是为检索精度服务：块越大，单块语义越杂，命中时给出的上下文精确度越低。

## 3. 索引构建

### 3.1 幂等设计

| 机制 | 做法 |
|---|---|
| 写入方式 | 按 `chunk_id` **upsert**，不用 add |
| 变更检测 | 比对 `content_hash`（正文 sha256 前 16 位），未变化的块跳过 embedding |
| 残留清理 | 集合内存在但当前文档已不存在的 `chunk_id`，按差集删除 |
| 验收命令 | 连续运行两次，集合计数必须不变 |

**为什么用内容哈希而不是"文件修改时间"：** mtime 会被 checkout、复制、格式化工具改动，
误判率极高；哈希是"内容是否真的变了"的唯一可靠判据。

**为什么 chunk_id 用标题哈希而不是节序号：** 节序号会随文档插入新章节整体后移，
导致所有 ID 变化、幂等失效（旧块残留 + 新块重复）。用标题哈希后新增章节不影响既有块。

实测：首次构建写入 67 块；第二次运行写入 0 块、未变化 67 块、计数仍为 67。

### 3.2 元数据 schema

| 字段 | 示例 | 用途 |
|---|---|---|
| `chunk_id` | `03_activation_funnel#9a377ae8#00` | 幂等主键 |
| `source_file` | `knowledge_base/03_activation_funnel.md` | 溯源 |
| `title` | 激活漏斗与数据限制 | 引用标注 `《标题》§章节` |
| `section` | 标准漏斗为什么不可构造 | 引用标注 + 定位 |
| `ordinal` | 0 | 节内块序号 |
| `content_hash` | `a1b2c3d4e5f6a7b8` | 变更检测 |
| `document_version` | 1 | front-matter 版本 |

### 3.3 Chroma 1.5 的一个硬限制（导致设计偏离）

设计文档 §5.2 原本要求把 `index_version` 写进 collection metadata。实测做不到：

- `collection.modify(metadata={"index_version": "..."})` 会**整体替换** metadata，
  把 `hnsw:space` 丢掉；
- 把 `hnsw:space` 一起传进去，直接抛
  `ValueError: Changing the distance function of a collection once it is created is not supported.`

距离度量一旦被静默改回默认 L2，检索语义会变但不会报错——这是最危险的一类问题。
**处置：collection metadata 创建后不再改动，索引版本写入旁挂文件
`data/chroma/index_meta.json`**，内容含模型名、维度、距离度量、构建时间、块数。

## 4. 检索配置

| 参数 | 值 | 依据 |
|---|---|---|
| `RAG_TOP_K` | 4 | 设计文档约定 |
| `RAG_MAX_PER_DOC` | 2 | 见下 |
| `QUERY_INSTRUCTION` | `""`（不加前缀） | 18 题对照实测无差异 |
| 距离度量 | cosine（向量已 L2 归一化） | `hnsw:space=cosine` |
| `RAG_DISTANCE_WARN` | 0.40 | 评估集实测，**弱证据**，仅作提示 |

### 4.1 单文档配额：一个被评估抓出来的真实缺陷

首轮评估发现跨文档题 X03（期望 `04` + `11` 两份文档）的 Top-3 **全部来自 `11`**，
Recall@3 只有 0.5。原因是同一份文档的相邻小节距离都很近，会把 Top-K 挤满。

加入"每份文档最多贡献 2 条"后：Recall@3 从 **0.9667 → 1.0000**，
跨文档 Recall@3 从 **0.8333 → 1.0000**。这是本项目 RAG 部分唯一一处
"指标驱动的代码修改"，且修改前后均在同一评估集上测量。

> **必须披露的方法论问题：** 这个改进是在看到评估结果之后做的，
> 所以评估集对这处改动而言已不再是严格的留出集。真实项目应另设一套
> 未参与调优的测试集来复核，本项目的诚实表述是"形成性评估"。

### 4.2 查询指令：实测无差异

BGE v1.5 中文版官方说明检索时无需指令。为不凭印象定值，用 18 题做了对照：

| 口径 | Hit@3 | Top1 准确率 | Recall@3 | MRR |
|---|---:|---:|---:|---:|
| 无指令 | 1.0 | 0.8667 | 1.0 | 0.9333 |
| BGE 中文指令 | 1.0 | 0.8667 | 1.0 | 0.9333 |

三项指标完全相同，故默认保持不加前缀。**注意"无差异"不等于"指令有害"**，
只能说明在这个 18 题的集合与这个模型上测不出差别。

## 5. 术语纪律

Chroma 返回的是**余弦距离**（0 最近、2 最远），不是概率，也不是相关度百分比。

- 代码与报告中只能写"距离"或"相似度分数"；
- **禁止**写成"置信度 0.87""匹配概率 87%"——那会让读者误以为是可信度；
- `distance > 0.40` 只能说"可能未覆盖知识库"，不能说"有 60% 概率没有答案"。
